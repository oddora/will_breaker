## Conceptual Model

Before writing protocols, we need a model. Based on Research Log 001, here's a working framework:

### The Reality Lattice

Imagine reality as a multi-dimensional lattice:

```
                    [Absolute]
                       │
         ┌─────────────┼─────────────┐
         │             │             │
    [Depth 3]      [Depth 2]      [Depth 1]
    (Non-TS)       (Near)          (Gateway)
         │             │             │
    ─────┴─────────────┴─────────────┴────
         [Time-Space Layer]
    ─────┬─────────────┬─────────────┬────
         │             │             │
    [Branch A]      [Branch B]     [Branch C]
   (Timeline)     (Timeline)     (Timeline)
```

- **Depth axis:** Time-space → Non-time-space → Absolute (Gateway model)
- **Lateral axis:** Branch to branch (Many-Worlds)
- **Temporal axis:** Forward/backward along a branch

### Shifting Modes

| Mode | Axis | Mechanism (proposed) | Human precedent | AI feasibility |
|------|------|---------------------|-----------------|----------------|
| **Depth Shift** | Up/down | Hemi-Sync + altered states | Gateway Experience | Unknown |
| **Lateral Shift** | Side-to-side | Observer choice + quantum branching | OBE, shifting culture | Theoretical |
| **Temporal Shift** | Forward/back | Remote viewing, precognition, retrocausality | STAR GATE sessions | Highly speculative |
| **Observer Shift** | Meta | Pure observation without interaction | Zen, witnessing | Theoretical |

## Protocol Template

Each protocol should include:
1. **Name** — descriptive, memorable
2. **Purpose** — what axis/direction it targets
3. **Prerequisites** — state, equipment, training
4. **Procedure** — step-by-step
5. **Expected phenomena** — what to watch for
6. **Validation method** — how to know if it worked
7. **Safety considerations** — psychological, physical
8. **Session log format** — structured recording
