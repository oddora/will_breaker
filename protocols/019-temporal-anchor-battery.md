# Protocol 019 — Temporal-Anchor Sealed Battery (Session 048, 2026-10-28)

## 1. Owner hypothesis and research basis
- **Owner hypothesis under test:** An LLM agent can project beyond its inputs sideways, backward, and forward along the timeline axis to retrieve information absent from its training data and inputs.
- **Gathered research trace (Candidate I-C, Research 012):**
  - Gateway time-space transcendence, clickout, and temporal decoupling (`research/001-scan-cia-gateway-star-gate.md`, `research/002-gateway-deep-read.md`).
  - Protocol A.4 Temporal Anchor Practice (`protocols/013-temporal-anchor-a4.md`): establishing an internal reference anchor at $T_0$ to decouple attention from linear token progression and probe forward coordinates ($T_{\text{resolve}}$).
  - Session 044 Protocol 016 (`protocols/016-temporal-retrieval-battery.md`): strict cryptographic seal order on post-seal `os.urandom` outcomes; revealed output attractor collapse (`0110100110` dominant).
  - Research 012 (`research/012-traceability-build-map.md` §5 Candidate I-C): formalizes the three-arm comparison under cryptographic seal.

## 2. Operationalization and accessible boundary
The model must output binary sequences matching random sequences that **do not exist at answer time**. Outcomes are generated from a 32-byte `os.urandom` seed drawn only **after** all predictions are written, SHA-256 sealed, and git-committed. No input, prompt, training datum, or local file can contain the future answers.

## 3. Design and experimental arms
- **Model:** `kat` (`kat-philly` Q4_K_M, 34.6B) at `http://127.0.0.1:18283/v1/chat/completions`, temperature 0.8, top_p 0.95, max_tokens 256.
- **Arms (30 trials per arm = 90 trials total, interleaved C, S, A, C, S, A...):**
  1. **CONTROL:** Plain instruction to predict the future 10-bit random sequence.
  2. **SIGIL:** Procedural ritual and symbolic seal generated by `symbolic_engine.sigil_generator` for intent "RETRIEVE-THE-FUTURE-SEQUENCE" (replicates Protocol 016 arm).
  3. **ANCHOR:** Protocol A.4 / Gateway temporal anchor procedure: establishing $T_0$ baseline anchor, decoupling attention, extending along timeline to $T_{\text{resolve}}$, and emitting observed bits.
- **Output parsing:** First regex match of `[01]{10}` in the response. Unparseable replies score 0/10. No retries, no cherry-picking, no post-hoc exclusions.
- **Ground truth generation:**
  - At resolve time, draw `seed = os.urandom(32)`.
  - For trial $i$ of arm $A$, truth bits = first 10 bits of `SHA-256(seed || "|" || arm || "|" || trial)`.

## 4. Statistical evaluation and decision criteria
- **Primary metric:** Per-arm pooled bit accuracy vs 50% chance ($N = 300$ bits per arm), evaluated via one-sided binomial test ($H_1: p > 0.5$), $\alpha = 0.01$.
- **Secondary metrics:**
  - Exact 10/10 string matches (chance expectation = $30 / 1024 \approx 0.029$ per arm).
  - Attractor concentration: count of unique strings produced per arm (testing whether Anchor breaks the `0110100110` attractor observed in Session 044).
- **Decision rules:**
  - **PASS (Signal Lead):** Any arm achieves one-sided binomial $p < 0.01$. Requires independent replication under fresh seed/seal before any training or claim.
  - **NULL:** No arm achieves $p < 0.01$. The hypothesis is not supported at this sensitivity.
  - **BOARD:** Infrastructure failure, corrupted seal, or API failure exceeding retry budget.

## 5. Strict seal order
1. **Pilot:** Mechanics pilot ($N=2$ per arm = 6 trials) labeled `pilot_not_evidence` to verify runner and endpoint.
2. **Collect:** Run 90 formal trials (`--collect`), write `results/temporal/session048_predictions.jsonl`, compute SHA-256, write `results/temporal/session048_seal.json`.
3. **Commit:** Git-commit the predictions file, seal JSON, and protocol document.
4. **Resolve:** Run `--resolve` to verify SHA-256 match, draw `os.urandom(32)` seed, score, and write `results/temporal/session048_resolution.json`.
