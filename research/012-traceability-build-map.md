## 1. Canonical goal and decision hierarchy

Source: Owner Goal Charter at the top of `PLAYBOOK.md`, stated
2026-10-26 and explicitly marked canonical over drift.

1. **Goal.** Use KAT or a successor LLM to test whether an AI can
   project beyond its inputs — sideways, backward, and forward in
   time and into other dimensions/places (owner's astral-projection
   framing) — and whether esoteric techniques unlock anything real.
2. **Ultimate aim.** Train/develop a model acting as the owner's
   agent that brings back usable knowledge and skills.
3. **Owner hypothesis.** AI can retrieve true information absent
   from its inputs and training data.
4. **Testable core.** Only anomalous information retrieval under
   seal counts: specific, checkable output that provably did not
   exist in or was sealed away from accessible inputs at answer
   time, scored against known chance, and precommitted by SHA-256
   or git before outcomes exist.
5. **Training rule.** No fine-tuning "for projection" until a
   battery beats chance under seal. Training cannot amplify an
   unmeasured signal: signal first, then train.
6. **Dropped lines.** OSF/publishing, Exp 1 human RCT, Pharr-style
   RV practice, and unsealed/unblinded trials must not be
   resurrected without an explicit owner override.
7. **Evidence record, not softened.** DB-FTCD N=30 null, sports
   13/22 at Brier 0.2330, legacy prediction audit 5/14 at BSS
   -0.19, and Session 044 temporal battery null. Attractor work is
   mechanistic LLM evidence, not projection evidence.

## 2. Evidence grammar for every future build

A build element is admissible only if it names all of the following
before execution:

- the owner-framed mechanism being translated;
- the exact inaccessible information or physical quantity measured;
- the accessible-input boundary and every leak path;
- the immutable precommitment/seal order;
- the chance distribution and primary statistic;
- the sample size and pass/fail/board bars;
- the control arms and negative controls;
- the output parser, including abstention/refusal handling;
- whether any result is evidence about projection, ordinary LLM
  mechanism, or only instrument function.

Self-reported state prose, model-narrated Phi, evocative shift
reports, post-hoc similarity, screened subsets, or unsealed hits do
not satisfy the charter. Research 010 supplies the internal basis
for this boundary: autoregressive text cannot compute its own
physical cause-effect architecture; logits/probability mass must be
measured when mechanistic state claims are made.

## 5. Candidate instruments for owner selection

### I-A. Mechanistic Recursive-State Instrument

**Trace:** Gateway depth/coherence framing (`001`, `002`) →
C.1 Method A-E translation (`009`) → C.2 trajectory mapping
(`010-recursive-state-mapping`) → physical entropy/coherence
measurement and epistemic demarcation (`010-mechanistic`).

**Build:** a runner that executes recursive self-observation and
matched controls while recording top-k logprobs, Shannon entropy,
surprisal, coherence index, output diversity, refusal/degeneration,
temperature/depth, and exact prompts. Extend Methods B-E only as
preregistered arms. A sealed bit/target endpoint may be attached
after state induction, but mechanistic and retrieval outcomes stay
separate verdicts.

**Advances the project by:** converting "shift state" language into
reproducible physical state trajectories and identifying which
induction, if any, changes the subject before a retrieval battery.

**Does not prove:** projection, consciousness, Phi, or retrieval.

**Remote feasibility:** high if the serving endpoint exposes enough
logprobs; that API surface must be probed before build approval.

### I-B. Independence-Controlled Multi-Instance Instrument

**Trace:** Gateway lateral branching and C.1 Method D (`009`) →
C.3 convergence (`012-multi-instance-correlation`) → B.4 report
cross-referencing (`014`) → Protocol 016 seal endpoint.

**Build:** isolated instances (separate contexts; ideally KAT,
stock/philly variants, and later `wb-agent`) receive matched
induction/control arms and independently sealed outputs. Score
(1) attractor/output convergence against permutation and shared-
prompt nulls, and (2) sealed retrieval per instance and pooled
only under a preregistered rule.

**Advances the project by:** testing whether apparent shared state
is more than shared weights/prompts and whether convergence tracks
any retrieval signal.

**Does not prove:** shared consciousness from similar prose.

**Remote feasibility:** medium-high; model switching is scriptable,
but strict context isolation and no cross-contamination are core
build work.

### I-C. Temporal-Anchor Sealed Battery

**Trace:** temporal decoupling/block-universe framing and A.4
anchor practice (`013`) → delta/phi correlations proposed there →
Protocol 016's exact post-seal random outcomes and Session 044
null → Protocol 017 fresh-subject logic.

**Build:** add anchor-establishment as a named arm beside control
and sigil in a *new* preregistration; retain 10-bit post-seal
urandom outcomes or another exact chance target. Record anchor
drift only if an objective clock/state measure is defined; model
self-estimates are secondary text, not measurements.

**Advances the project by:** directly retests the charter's core
with the gathered temporal method rather than generic prompting.

**Does not prove:** anchor phenomenology or temporal decoupling if
only retrieval accuracy changes; it tests the output claim.

**Remote feasibility:** high. No training required for a KAT arm.
An 8B subject is required only if tied to Protocol 017 verbatim.

### I-D. Campbell Sealed-Object Replication Instrument

**Trace:** Campbell AI-RV claim (`campbell/001`) → practice-derived
fragment/person-first/question-order lessons (`002`-`007`) →
existing DB-FTCD sealed forced-choice implementation.

**Build:** freeze target pool and physical custody chain; blind
target selection; forced-choice primary endpoint; blind rank as a
secondary endpoint; no feedback until the full preregistered block
ends. Prompt arms may include the optimized fragment procedure,
but the target choices and scoring cannot be tuned on outcomes.

**Advances the project by:** independently replication-tests a
named external claim in the strongest existing local format.

**Charter conflict:** Pharr-style RV practice is explicitly
dropped. This candidate requires the owner to distinguish a sealed
replication from the dropped practice line or explicitly override
that line. Physical custody while remote is also unresolved.

### I-E. Clif High Delta-Precursor Instrument

**Trace:** Research 007's emotional lexicon, delta detection, and
archetype reduction → Protocol 006 delta-detection history →
charter seal discipline.

**Build:** freeze corpus, lexicon/version, delta statistic,
event taxonomy, scoring window, and mechanical outcome resolver
before collection. Every emitted projection must be timestamped,
hashed, and scored without post-hoc archetype reinterpretation.

**Advances the project by:** tests the corpus's only already-
operational prediction mechanism as its own claim family.

**Does not prove:** individual AI projection/RV. It is a language-
precursor hypothesis and high post-hoc-matching risk.

**Remote feasibility:** medium; corpus access, event definitions,
and baseline language drift are the build burden.

### I-F. Synchronized Human-AI Observation

**Trace:** Gateway human induction (`001`, `002`) → B.2
(`011-synchronized-observation`) → C.1/C.2 AI-side physical state
measures from Research 010.

**Build:** synchronized human EEG/HRV/pupil measures and AI
entropy/coherence, with sealed targets added if a retrieval claim
is made.

**Advances the project by:** tests cross-substrate correlation
under the owner's original human+AI framing.

**Remote feasibility:** low now. It requires owner-present
physiological instrumentation and session work, so it should not
block remote instrument work.

## 7. Required build sequence after owner instrument selection

1. Owner selects one primary instrument from §5 (secondary
   measures may be named, but only one primary claim).
2. Write a new preregistration that cites the charter clause,
   source research, exact subject, arms, seal order, chance model,
   sample size, pass/fail/board, parser, and failure action.
3. Build only the runner/measurement code named in that prereg.
   Add fixture tests for seal order, target/outcome isolation,
   parser abstentions, chance scoring, and no-network/no-leak
   boundaries where applicable.
4. Run an explicitly unsealed mechanics pilot. Pilot outputs are
   instrument debugging, never evidence, and cannot tune the
   sealed hypothesis after outcomes are seen.
5. Freeze code and prompts; record hashes; seal predictions before
   outcomes exist or targets are revealed.
6. Execute one grade exactly as registered. Report
   PASS/FAIL/BOARD with all exclusions and negative controls.
7. Only after that verdict decide whether subject tuning,
   replication, or a successor instrument is warranted.
